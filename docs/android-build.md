# Heirloom Android app (Solana dApp Store)

The Android app is a thin shell around the live site **https://heirloom.tumoolo.tech** (the devnet chain-mode
Vercel project `heirloom-devnet`). Plan and decisions: [solana-mobile-plan.md](solana-mobile-plan.md).

| | |
|---|---|
| Tool | Solana Mobile CLI `solana-mobile` **0.6.0**, `webshell` command (the wrapper Solana Mobile's docs now recommend for web apps, Nov 2026) |
| Kind | Android **WebView shell**, not a Trusted Web Activity. Solana Mobile's docs say TWA wrappers (Bubblewrap) can break wallet connections; the shell handles `solana-wallet:` intents natively, so Mobile Wallet Adapter keeps working as Chrome adds Local Network Access limits |
| Package id | `tech.tumoolo.heirloom` |
| App name | Heirloom |
| Version | versionCode **1**, versionName **1.0.0** (minSdk 28 / Android 9, targetSdk 37) |
| First build | 15 Nov 2026, `app-release.apk` 2.08 MB (2 080 151 bytes), APK Signature Scheme v2 |
| Start URL | `https://heirloom.tumoolo.tech/` (the landing page; the web manifest's own `start_url` is `/chat`) |
| Colours | splash, launcher-icon background, window and system bars black `#000000` (the site is night by default) |
| Icons | from the site's web manifest (generated by the CLI into the adaptive launcher icon) |
| Signing key | RSA 2048, SHA256withRSA, alias `heirloom`, valid until 2 Apr 2054 |
| Signer SHA-256 | `AC:BB:AF:D1:17:3F:13:DE:80:39:D4:E7:CF:3E:E7:59:10:F2:EC:F7:9F:93:FC:C5:5E:2F:C5:5B:27:9D:35:E9` (public) |

Because the shell loads the live site, **web changes reach phones without a new APK**. A new APK is only needed when
the shell itself changes (name, icon, colours, package settings, a newer CLI template).

## Where things live (outside git)

```
<android build folder>\                             NOT a git repo, never commit any of it
  keys\heirloom-release.keystore                     the signing key (PKCS12)
  android\                                           the generated Android project (Gradle)
    twa-manifest.json                                CLI config: package id, host, start URL, key path + alias
    gradle.properties                                SOLANA_MOBILE_URL / _APPLICATION_ID / _VERSION_CODE / _VERSION_NAME
    app\build\outputs\apk\release\app-release.apk    the signed release APK
  build.log                                          the last build's output
```

> **BACK UP BOTH KEY FILES NOW** (the keystore and its password): copy them to a password
> manager or an encrypted USB drive, and keep a second copy somewhere else. Every update to the dApp Store listing must
> be signed with this same key. **If the keystore or its password is lost, the app can never be updated**; it would
> have to be published again as a new app under a new package id. Never put either file in the repo, a chat, an email
> or a cloud folder that isn't encrypted.

Small changes made to the generated project by hand (redo them if you ever re-run `webshell init --force`):
- `app/src/main/res/values*/themes.xml`: `android:windowBackground` black, so there is no white flash before the page.
- `ui/theme/Theme.kt`: the shell always uses a black dark scheme (no Material You colours); pull-to-refresh spinner amber `#F0A35E`.
- `MainActivity.kt`: `enableEdgeToEdge(SystemBarStyle.dark(BLACK), …)`: black status and navigation bars with light icons.

## Rebuild

Needs JDK 17+ and the Android SDK (`%LOCALAPPDATA%\Android\Sdk`; the build downloads any missing platform itself).
`npx solana-mobile@0.6.0 doctor` checks the setup.

```bash
# Git Bash
cd /c/Users/tumom/Hackathons/heirloom-android
export ANDROID_HOME="$LOCALAPPDATA/Android/Sdk"
read -rs SOLANA_MOBILE_KEYSTORE_PASSWORD && export SOLANA_MOBILE_KEYSTORE_PASSWORD   # from the password manager
export SOLANA_MOBILE_KEY_PASSWORD="$SOLANA_MOBILE_KEYSTORE_PASSWORD"
npx solana-mobile@0.6.0 webshell build android
```

Without the two variables the build asks for the password. The APK is
`android\app\build\outputs\apk\release\app-release.apk`.

**Bump the version for every store update** (the dApp Store refuses an APK whose versionCode isn't higher): edit
`android\gradle.properties`, e.g.

```
SOLANA_MOBILE_VERSION_CODE=2
SOLANA_MOBILE_VERSION_NAME=1.0.1
```

then rebuild. Never reuse or lower a versionCode.

**AAB:** not built. The webshell CLI only produces an APK, and the dApp Store takes APKs (its docs say an App Bundle
must not be submitted). If Google Play is ever wanted, `android\gradlew.bat bundleRelease` in the project can make one.

## Verify a build

```bash
BT="$LOCALAPPDATA/Android/Sdk/build-tools/36.0.0"
APK=/c/Users/tumom/Hackathons/heirloom-android/android/app/build/outputs/apk/release/app-release.apk
"$BT/apksigner.bat" verify --print-certs "$APK"     # Signer #1 certificate SHA-256 digest must equal the fingerprint above
"$BT/aapt.exe" dump badging "$APK" | head -3       # package: name='tech.tumoolo.heirloom' versionCode='1' versionName='1.0.0'
```

Checked on 15 Nov 2026: `apksigner` "Verifies" (v2, 1 signer, SHA-256 matches), `aapt` package/version as above,
and on an Android 16 (API 36) x86_64 emulator the APK installed and opened the live site full-screen, black bars,
night theme. Not yet checked: a real phone, MWA wallets, the back button.

Install on an emulator or a phone with USB debugging: `npx solana-mobile@0.6.0 device install <apk>` (or `adb install -r <apk>`).

## Digital Asset Links

The site serves `app/public/.well-known/assetlinks.json` (package `tech.tumoolo.heirloom` + the SHA-256 above), with
`Content-Type: application/json` set in `next.config.ts` `headers()`. There is no middleware, proxy or redirect in
the app, and the CSP only applies to pages, so nothing blocks it.

A WebView shell does **not** need Digital Asset Links (Solana Mobile's docs say so); the file is there so the same key
also works for a Trusted Web Activity build or Android App Links later, and it costs nothing. If the signing key
ever changes, update the fingerprint in that file.

Check once it is deployed (after `agent/apk` is merged to `main` and Vercel has redeployed `heirloom-devnet`):
1. https://heirloom.tumoolo.tech/.well-known/assetlinks.json returns the JSON with `content-type: application/json`
   (`curl -sI https://heirloom.tumoolo.tech/.well-known/assetlinks.json`).
2. Google's Statement List Tester:
   https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://heirloom.tumoolo.tech&relation=delegate_permission/common.handle_all_urls
   must list a statement with `"packageName": "tech.tumoolo.heirloom"` and the fingerprint above.
   (The form version is at https://developers.google.com/digital-asset-links/tools/generator.)
